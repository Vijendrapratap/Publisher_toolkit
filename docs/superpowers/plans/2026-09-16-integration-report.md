# Local Supabase + OpenRouter integration — report

Plan: `docs/superpowers/plans/2026-09-16-supabase-and-openrouter.md`

## What changed, per file

**Part 1 — OpenRouter as the AI provider**

- `package.json` / `package-lock.json` — added `@openrouter/ai-sdk-provider@3.0.0`.
- `lib/providers/ai.ts` — rewritten. `isAiConfigured()` now checks `OPENROUTER_API_KEY` only (dropped `AI_GATEWAY_API_KEY` / `VERCEL_OIDC_TOKEN`). Added `getAdCopyModel()`, which calls `createOpenRouter({ apiKey })` *inside* the function body — no client is built at import time, so importing this module with no key (the local-mode default) can't throw. Model id comes from `OPENROUTER_MODEL`, falling back to a `DEFAULT_MODEL` constant.
- `lib/services/ads/copy.ts` — `attemptGeneration` now passes `model: getAdCopyModel()` instead of the bare gateway string `'anthropic/claude-sonnet-5'`. Tone in the prompt, platform filtering, retry-once, and the `[]`-on-repeated-failure behavior are all unchanged. The `!isAiConfigured()` → `sampleAdCopy` branch is unchanged.
- `lib/providers/status.ts` — no code change needed; it already delegates to `isAiConfigured()`, which now reflects OpenRouter automatically.
- `.env.example` — replaced `AI_GATEWAY_API_KEY=` with `OPENROUTER_API_KEY=` and `OPENROUTER_MODEL=`, same "everything optional" framing.
- `lib/services/ads/copy.test.ts` — `AI_GATEWAY_API_KEY` → `OPENROUTER_API_KEY` in `beforeEach`/`afterEach` and the two local-mode tests. No assertion intent changed.
- `lib/providers/status.test.ts` — key list changed from `['CLERK_SECRET_KEY', 'BLOB_READ_WRITE_TOKEN', 'AI_GATEWAY_API_KEY', 'VERCEL_OIDC_TOKEN']` to `['CLERK_SECRET_KEY', 'BLOB_READ_WRITE_TOKEN', 'OPENROUTER_API_KEY']` (no gateway/OIDC concept left to test).
- `lib/providers/ai.test.ts` — new. Two tests: `getAdCopyModel()` falls back to `anthropic/claude-sonnet-5` when `OPENROUTER_MODEL` is unset, and reads it when set.

**Model id:** `anthropic/claude-sonnet-5`. **Verified** — the plan's network access worked (`curl https://openrouter.ai/api/v1/models`, no auth needed), and `anthropic/claude-sonnet-5` is present in the live model list, alongside `anthropic/claude-sonnet-4.6`, `-4.5`, `-4` and a `claude-sonnet-latest` alias. Used the exact live id rather than the plan's documented fallback (`anthropic/claude-sonnet-4.5`), since verification succeeded.

**Part 2 — Local Supabase for dev**

- `supabase/config.toml` — created via `supabase init --yes` (non-interactive; no prompt was hit). `project_id` changed from the auto-derived `platform-shell` (the worktree dirname) to `publisher-toolkit` per the plan. Ports match the plan's stated facts: API 54321, Postgres 54322 (shadow 54320), Studio 54323.
- `supabase/.gitignore` — generated by `supabase init` itself (`.branches`, `.temp`, plus dotenvx entries); commits alongside `config.toml`. Confirmed with `git status --ignored` that `supabase/.temp/` is excluded. No root `.gitignore` change was needed — the nested ignore file already covers it.
- `scripts/dev.mjs` — database selection is now a three-way branch: (1) `DATABASE_URL` set → used as-is; (2) else, `isPortOpen(54322)` (reused from `embedded-db.mjs`, not reimplemented) → uses `postgresql://postgres:postgres@127.0.0.1:54322/postgres`; (3) else → existing embedded-postgres path, byte-for-byte the same behavior as before. Each branch prints one `[db] ...` line naming its choice. Supabase is never started by this script — only detected.
- `README.md` — added a "Database modes" section listing the three options and the order dev.mjs tries them.
